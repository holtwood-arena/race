# 优化方法论笔记

随练习持续补充。每条结论都要能指向一次测量。

## 通用顺序

1. **正确性先行**：输出 hash 与参考一致前，速度没有意义。
2. **先测量再改**：perf/profiling 找出热点，不猜。
3. **大头优先**：wall time 权重最大；解析/IO 常常是隐藏大头。
4. **内存布局 > 算法微操**：在这个规模上，cache 命中率常比渐进复杂度更值钱。
5. **并行按物理核设计**：目标 6C12T，不超额订阅；注意共享内存上限。
6. **每个实验可回退**：失败的尝试记入 PERF.md，它们是判断力的证据。

## 常见收益点（按赛道）

- **解析**：手写行级解析 >> 通用 reader；时间戳解析常被低估；SIMD/SWAR 定位分隔符。
- **分位数**：避免全排序——直方图/快速选择/近似算法（注意正确性门槛是 byte-identical）。
- **CSV**：引号状态机 + 块边界处理（引号内换行是边界对齐的坑）。
- **索引**：构建与查询抢同一份时间预算；posting list 压缩与跳过指针。
- **图**：CSR 布局 + 快速解析优先于高级最短路索引。
- **分配器**：mimalloc/jemalloc 或 arena/pool 常是"免费的 20%"。

## 反模式

- 为省内存牺牲时间：K 公式里 T 权重 0.50 vs M 0.20，账算得过来。
- 依赖堆砌：每个直接依赖 ×0.9（D 轴），零依赖起手是免费优势。
- 笔记本上过拟合 cache 参数：目标机 L3 16 MB、AVX2 无 AVX-512。
